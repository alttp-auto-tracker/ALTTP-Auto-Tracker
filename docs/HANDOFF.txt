================================================================================
1. WHAT THIS PROJECT IS
================================================================================
Web-based A Link to the Past randomizer auto-tracker.
Connects to SNI / QUsb2Snes for live SRAM. Practice vs Race Legal modes.
Stream overlay for OBS. LAN sync so phone and PC share notes/modes/prizes
while OBS holds SNI as the live host.


================================================================================
2. HOW TO RUN
================================================================================
  cd alttpr-tracker
  python3 tracker-server.py          # or: python tracker-server.py

  Main:     http://localhost:8000/tracker.html
  Stream:   http://localhost:8000/streamer.html
  Phone:    http://<PC-LAN-IP>:8000/tracker.html

  OBS: one Browser Source → streamer.html (use Streamer URLs modal).
  SNI rule: only ONE browser can attach at a time.
  Recommended: OBS = host (SNI); phone/PC = controllers (no SNI).

  After code changes: hard-refresh + bump service-worker CACHE_VERSION
  (or Unregister SW in DevTools). Restart tracker-server.py for API changes.


================================================================================
3. MODES
================================================================================
  World:      Standard / Open / Inverted          (worldMode)
  Keys:       Standard / Keysanity / Keys / MC / MCS / MCBK
  Bosses:     Normal / Shuffled
  Entrances:  Vanilla / Shuffled
  Race mode:  Practice vs Race Legal (raceMode)

  LOCKED DURING RUN (timerAutoStarted):
    World / Keys / Bosses / Entrances + Practice/Race Legal button
    Unlock on timer Reset (local or LAN). Controllers lock when host
    live-state says run started.

  Streamer URL can bake modes: ?world=…&keys=…&boss=…&entrances=…
  Live changes sync via /api/rando-modes + SSE.


================================================================================
4. ARCHITECTURE (HOST + CONTROLLERS)
================================================================================
  HOST (streaming PC — streamer.html in OBS)
    - Attaches to SNI
    - Owns live SRAM → items, timer, map, rain state
    - POSTs /api/live-state each poll so phones can mirror

  CONTROLLERS (phone / laptop tracker.html)
    - Do NOT attach SNI (?controller=1 or Controller mode toggle)
    - Pull / SSE live-state for items/map/timer display
    - POST control commands (prizes, medallions, entrances, run reset/finish)
    - Edit entrance notes / modes (synced)

  What syncs live:
    - World / Keys / Bosses / Entrances + raceMode
    - Entrance pairings
    - Prize board + MM/TR medallions
    - Run reset / finish (/api/run-control)
    - Live item/map/timer snapshot (/api/live-state)
    - Run history library (/api/run-history) — merge by id + deletedIds
    - Spoiler-route / coaching HTML (/api/coaching) — Practice only

  What is local to the SNI host until published:
    - SRAM reads (items, room, game mode)
    - Active run session construction (report data)
    - Spoiler placements (from seed load; Practice)

6. SERVER APIs
================================================================================
  GET/POST /api/entrance-pairings
  GET/POST /api/rando-modes          (+ raceMode)
  GET/POST /api/prizes               assignments, claims, mmMed, trMed
  GET/POST /api/live-state           host publishes; controllers mirror
  GET/POST /api/run-control          {action: reset|finish|start}

  GET     /api/sync-events           SSE: modes, entrances, prizes,
                                     live-state, run-control, run-history,
                                     coaching

  Persist files next to server:
    .entrance-pairings-sync.json
    .rando-modes-sync.json
    .prizes-sync.json
    .run-control-sync.json
    .run-history-sync.json         (includes deletedIds)

7. TIMER AUTO-START
================================================================================
  Auto-start ONLY on transitions — never while already mid-run after reset:

  1) Room transition into Link's House (0x104)
  2) Game-mode transition from title/file into playable (0x07–0x0B)

  On Reset: pin previousRoom / previousGameMode so standing mid-dungeon
  does NOT re-arm. Runner must house / title→play / manual Start.

  When timerAutoStarted: lock rando mode selects + Practice/Race button.


================================================================================
8. CONTROLLER MODE + LAYOUT FLASH
================================================================================
  Toggle: "Controller mode" / "Full tracker" (header, same slot both modes).
  ?controller=1 also forces controller layout.

  Flash: flashLayoutChange() in controllerMode.js — inline-styled overlay
  + centered banner ("Controller Mode" / "Full Tracker Mode"). Holds ~550ms
  then fades. Do NOT put overflow:hidden on body (clips fixed flash);
  overflow-x only on .wrap.

  Controller: hide Connect + Streamer URLs; force compact items; hide
  Start/Reset (LAN control only); denser item grid on phone.


================================================================================
9. SPOILER ROUTE (Practice only) — replaced "I'm Stuck"
================================================================================
  UI: collapsible "Spoiler route" panel (tracker.html + streamer.html).
  Race Legal: panel hidden.

  Load spoilers:
    - Automatic: Load non-race seed (seed.js → ingestSpoilerFromSeedJson)
    - Manual fallback: details "Paste spoiler manually" (JSON or Location: Item)

  "Next obtainable item" (spoiler.js):
    1. Walk PROGRESSION_PRIORITY (boots → glove → hammer → hookshot → …)
    2. Find placements for first missing item
    3. Filter to checks reachable with public logic (loc.need / entryNeed)
       + name hints (e.g. "Torch" requires boots — not just dungeon entry)
    4. Prefer closest to player; draw map guide line (showStuckMapGuide)
    5. If none reachable: show next priority item as unreachable (rose card)

  Map guide helpers still live in map.js (stuck-guide-line, stuck-target).
  Coaching LAN sync targets #spoilerSuggestion (not stuckSuggestion).

  IMPORTANT: Matching "Desert Palace - Torch:1" to DP entrance alone is NOT
  enough — isDetailedDungeonCheck + locationNameRequirementsMet block that.


================================================================================
10. MAP / RAIN / ESCAPE SEWERS
================================================================================
  Standard rain: progress < 2 on $7EF3C5 (hasClearedRain / isRainState).

  Escape Sewers marker:
    - Entry after rain: Sanctuary or HC front door — NO gloves required
    - Full green (need): can reach area AND lamp AND bombs
        (Dark Cross needs lamp; Secret Room wall needs bombs)
    - Yellow (partialNeed): can reach but missing lamp and/or bombs
    - During rain: corridor reachable; still only full-green with lamp+bombs
      if those checks remain

  Sanctuary: rain corridor OR canReachLightWorldCheck after rain.

  Partial markers: solid full yellow square (not half-fill gradient).

11. RUN HISTORY DELETE
================================================================================
  Deletes were undone by LAN union-merge. Fixed with tombstones:

  Client: deletedRunIds Set (localStorage) → POST deletedIds
  Server: merge_run_history(incoming, deleted_ids) removes those ids;

  applyRemoteRunHistory: drops deleted ids, never re-adds them

  Restart tracker-server.py after server-side changes.
